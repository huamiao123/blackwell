# V4.1 实施方法与 Gate 边界

采用 RQ1→RQ2→RQ3 的独立证据链，详见研究假设。当前仅 Gate 0/1。

1. 历史来源与源码/指标可用性审计，不运行模型。
2. 数据集和配置冻结，CPU验证模板、输入、长度、Hash与分析算法。
3. 人工验收 Gate 0/1 后，在明确空闲授权窗口手动运行一个 E1/E2 配置。
4. P0至少5次，精度交替，关键结果跨独立进程；P1与P2分别采集完整推理。
5. 验收真实GPU路径、Schema、身份、时间域、Replay、实际256Decode及Profiler扰动。
6. 重点算子与机制证据达到要求后选择一次有限并发试点，不一次展开整个矩阵。

E3–E7、Teacher Forcing、动态到达、Prefix Cache、额外长度、辅助压力和实际消费者
都是后续经人工检查的扩展。当前配置文件和设计不构成执行授权。

部署与运行分离。部署不回写 `raw/`、运行命令或监督日志；源代码、数据和派生分析
只在没有本项目活动试验时同步。每次监督记录独立保存，不依赖易被覆盖的汇总日志。

CPU计划命令默认不查询GPU。执行需显式 `--execute`、启用且未过期的窗口文件、
Gate审阅记录、E1/E2白名单、设备UUID及空闲检查。无空闲则立即拒绝，不等待轮询。
出现自动控制器或外来GPU任务，停止自己的进程组；不操作其他进程。
所有运行有硬超时和缓存路径限制，没有后台排队器、监视器或自动Gate推进。

现有监督器的CPU解析/授权门禁测试可复用，sudo NSYS 下的完整进程终止及实际GPU
清理仍需未来验收。若出现自己遗留的无法清理进程，停止本轮，不继续盲目重跑。

当前目录的性能CSV只有表头，表示未采集；不是零性能数据。CPU SQLite测试文件
均位于被忽略的 `local_cache/`，结束后清理，不混入raw/。无有效实验数据不绘制结果图。
