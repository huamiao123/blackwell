# 64 CTA Tensor Core 探针的跨投影实测

在 RTX 5090 上复用上一轮 QKV 实验的同一辅助任务，测试 O Projection、FFN Down 和 Gate/Up。O 与 Down 两者的 CTA 规模和单 CTA 资源在同一精度内相同，归约维度及主投影时长不同。Gate/Up 提供主 Grid 超出 SM 数量的对照。

## 配置与来源

| 主投影 | GEMM M/N/K | NVFP4 主 Grid | BF16 主 Grid |
| --- | --- | ---: | ---: |
| QKV（继承） | 8 / 6144 / 4096 | 48 | 384 |
| O | 8 / 4096 / 4096 | 32 | 256 |
| Down | 8 / 4096 / 12288 | 32 | 256 |
| Gate/Up | 8 / 24576 / 4096 | 192 | 1536 |

运行固定第 18 层，选择器从 Gate 3 的逐层资源表及归档 CUDA Graph 活动关联四个模块的 CUDA Tools ID、参数大小、Grid/Block 及共享内存。回放保留真实 checkpoint 权重和 vLLM 原生计算路径，输入为已核验的一致合成张量。每个进程三次精确回放，并核验九组条件的主投影与探针输出。NVFP4 量化在起跑前完成，测量范围为独立核心投影。 [四个归档节点的选择证明](../configs/extended_kernel_selection.json)

辅助工作固定为 64 CTA、256 个 16×16 tile、每 tile 128 轮 BF16 K=16 MMA，逻辑工作 268,435,456 FLOP。P0 独立运行六配对块，用 GPU Event 测同一组 A Alone/B Alone、并发和实测等工作量串行条件。P2 另行测量 CUDA Kernel 区间。两类结果分别统计。 [上一轮同一探针的 QKV 结果](qkv_gateup_20261119.md)

## GPU 时间线

| 主投影 | 精度 | A Alone | B Alone | B 与 A 重叠 | B 在 A 后的尾部 |
| --- | --- | ---: | ---: | ---: | ---: |
| O | NVFP4 | 17.089 μs | 16.640 μs | 16.609–16.672 μs | 0.480–0.512 μs |
| O | BF16 | 19.233 μs | 16.640 μs | 18.241–18.401 μs | 0.320–0.960 μs |
| Down | NVFP4 | 44.001 μs | 16.672 μs | 17.377–17.408 μs | 0 μs |
| Down | BF16 | 70.434 μs | 16.928 μs | 19.232–19.393 μs | 0 μs |

以上为各精度各一份 P2 中两种提交顺序的值。Down 的四次观测中 B 既无前段也无尾部，256 个输出 tile 完整在 A 的 GPU 活动区间内执行。O 存在短尾部，Kernel 时间重叠比例无法换算窗内完成的 tile 数。两个算子主 Grid 相同，观察到的尾部不同。 [O 时间线](analysis/o_proj_grid64_tensor_light_trace/qkv_pilot_summary.csv) [Down 时间线](analysis/down_proj_grid64_tensor_light_trace/qkv_pilot_summary.csv)

实际 GPU 计时中，NVFP4 Down 的 B 完成时间比 A 结束早 26.27–26.34 μs。上一轮 QKV 余量约为 0.35–0.38 μs。Gate/Up 的 NVFP4 核心投影约为 67 μs，探针在其开始约 46.6 μs 后才进入，在 A 结束后又持续 60.58–60.96 μs。主投影时长与可观察的辅助执行时间需要共同考虑。[Gate/Up 同探针时间线](analysis/gate_up_proj_grid64_tensor_light_trace/qkv_pilot_summary.csv)

每行采用 AB、BA 两种提交顺序的平均值范围。联合速度以同一提交顺序的实测串行为基线。

[四投影 P0/P2 对照数据](analysis/tensor64_projection_comparison_20261119.csv) · [P0 配对区间图](figures/tensor64_projection_comparison_20261119.png)

六个 O 配对块中，NVFP4 的探针吞吐保留 91.07%–92.09%，BF16 为 82.39%–83.43%。NVFP4 相对 BF16 的配对提升为 AB +8.66 个百分点（95% 区间 +4.07 至 +13.24）、BA +8.68（+7.81 至 +9.55）。NVFP4 主任务平均延长 1.97%–2.87%，区间上界仍超过 5%。联合收益在 AB 上有明确跨精度差异，BA 的差值区间跨零。[O 六块 P0](analysis/tensor_light_o_grid64_p0_statistics.csv)

六个 Down 配对块中，NVFP4 的主投影平均变化为 −0.05% 至 +1.07%，95% 区间上界分别为 2.90% 和 4.71%。探针吞吐保留 92.21%–93.08%，比 BF16 高 9.51–9.99 个百分点。联合完成的 (S) 为 NVFP4 1.35–1.37×，BF16 约 1.25×。两个提交顺序的跨精度配对差值区间均在零以上。P0 的结果支持 NVFP4 Down 的低干扰共存，P2 证实了本次探针的全部完成窗口。[Down 六块 P0](analysis/tensor_light_down_grid64_p0_statistics.csv)

Gate/Up 的两种提交顺序在 NVFP4 上都使联合时间比实测串行长约 41%–42%。主投影延迟的变化在重复波动范围内，辅助工作仍显著受限。独立 P2 的 CUDA Kernel 区间与 P0 Event 包络具有不同边界，P2 主要用于定位迟入场和尾部。固定探针跨投影对照表明，长运行时间只有在探针及时入场并保有执行能力时才能转化为可用窗口。[Gate/Up 六块 P0](analysis/tensor_light_gate_up_grid64_p0_statistics.csv)

## 实验范围

本次同一探针的比较适用于独立投影。由实时函数属性与保留共享内存计算的必要条件，允许检查候选混合 CTA 布局。轨迹可见的探针入场延迟支持投影间调度压力不同的解释，未直接定位到具体 SM 或管线。完整 vLLM Decode Graph 中，旁路工作还需要在对应阶段入场，并赶在真实消费者的截止时间之前完成。完整模型的缓存行为和推理端到端收益仍需测量。[时序关联与资源约束](../../gate4_residency/analysis/live_tensor_extension_20261119.csv)

本轮新增六份 P2 和三个六块 P0 数据集，共 36 个独立 P0 进程及 324 个配对条件观测。所有输出及负对照通过，29 项 CPU 检查通过，旧 QKV P0 统计按字节复现。12:06 复查共享 RTX 5090 无计算进程。
