# 研究假设、反证与证据等级

RQ1、RQ2、RQ3 独立判断。以下均为待验证假设，不是结果。

| 假设 | 最小可接受证据 | 反证或不能支持的条件 |
|---|---|---|
| H1：精度改变资源画像 | 匹配完整推理负载、实际 Kernel 路径、独立重复、已核对时间域的阶段指标 | 差异低于运行/采样波动，或由模板、长度、调度、后端变化解释 |
| H2：资源画像改变竞争 | 相同 B 工作量、配对 Block、BF16/NVFP4 的双向损失、实际 GPU 重叠 | 只有绝对完成时间不同；未重叠；工作量或缓存前提不一致 |
| H3：竞争具有阶段依赖性 | B 的实际 GPU 区间在 P/D/L/M 中可定位，阶段指标有重复差异 | 仅 CPU 提交时刻不同；B 跨阶段却按预期标签归类 |
| H4：共存机会可利用 | 主延迟初始损失 <=5%，P95 无明显恶化，B 输出有效，实测串行比较有收益 | B 主要在 A 后完成；串行已更快；仅增添无用运算或不可重复 |
| H5：可转化为推理优化 | 有真实消费者、满足依赖、无重复无效工作，P0 E2E 或服务吞吐改善 | 只有人工探针工作量或利用率升高；消费者未接入；只改善局部小项 |

5% 是初始研究阈值。正式判定应同时报告配对差值、逐次样本、标准差与置信区间，
不以单次最佳样本或阈值擦边取胜。P95 检查同时涉及逐请求和独立 Run 的稳定性；
256 个相邻 Decode Step 不是 256 个独立重复。

瓶颈判断需要额外证据：较高 DRAM 指标不能独自证明唯一带宽瓶颈；缺少 L2、
Warp Stall 或 Eligible Warp 时，只保留候选解释。理论 CTA 上限不证明实际调度，
实际 Kernel 时间交集不证明同 SM 共驻。

Dense Qwen3 固定形状下，内容组主要用于泛化和排除 Token/调度混杂。发现内容
差异时先检查生成长度、EOS、前缀命中、模板、实际 Batch 与 Kernel 形状，再解释
硬件机制。自然 EOS 与固定长度分组报告。

所有结论使用 `VERIFIED / PARTIALLY_SUPPORTED / UNVERIFIED / CONTRADICTED`，并绑定
配置、数据集、样本、测量范围、证据与适用边界。**当前 RQ1–RQ3 的 V4.1 新 GPU
结论全部为 UNVERIFIED。CPU 数据与测试的 VERIFIED 仅适用于 CPU 范围。**
