# Gate 4.4 完整 E2 并发实验

在 RTX 5090 上沿用已有 E2 的 Qwen3-8B BF16 与原生 NVFP4 配置。每次完整执行 8 条合法固定输入，每条 2048 个输入 Token、257 个输出 Token，并核验实际调度的 256 个 Decode Step。使用 FP8 E4M3 KV、已验证 CUDA Graph 路径，Prefix Cache 和 Chunked Prefill 均关闭。

## 测量范围和控制

- A 为预编码输入的完整 vLLM 推理。TTFT 从本地引擎入队计，ITL 从同一条请求的相邻 Token 计，TPOT 为该请求首末 Token 间隔除以 256。
- B 为与此前四投影实验一致的 BF16 Tensor Light。每次 64 CTA，完成 256 个 16×16 输出 tile，各 128 轮 BF16 MMA。B 使用独立 CUDA Stream 和预备缓冲区，保持原模型 Graph。每个注入目标的输出缓冲区初始为 NaN，计时结束后逐值核验。
- Decode 条件在 Scheduler Iteration 33–64 各提交一次。分别执行主任务单独、空提交、阶段内实测串行和并发。串行由主 Stream 等待 B 完成后提交目标 replay。P0 中每种精度用一个已加载引擎完成五个配对块，四种条件交替执行。
- P2 用 Nsight 把 CUDA API correlation ID 和 NVTX 标记关联到真实 Kernel。A 的 Kernel 区间取并集后与 B 求交。P0 和 P2 的性能时间独立，CPU NVTX 区间只用于识别真实 GPU launch。完整请求计时以 A 返回及随后全设备 drain 两种边界分别记录。
- P0 的辅助事件区间可包含设备队列等待和提交影响。前置 B Alone 验收不处在 E2 同一时钟与调度状态。正式比较辅助任务竞争时，优先使用独立 P2 中实测阶段串行与并发的同工作量 B Kernel 区间。后者目前每个条件仅一份轨迹。

## Decode 机制证据

| 主任务精度 | 并发实际重叠 | 实测串行重叠 | 并发 B Kernel 中位时长 | 阶段串行 B Kernel 中位时长 | 阶段串行归一化 B 吞吐 |
| --- | ---: | ---: | ---: | ---: | ---: |
| NVFP4 | 32/32 | 0/32 | 20.449 μs | 16.161 μs | 79.3% |
| BF16 | 32/32 | 0/32 | 17.600 μs | 15.808 μs | 89.7% |

在各自轨迹中，探针执行区间与实际 A Kernel 区间的平均重叠比例分别为 93.2% 和 91.4%。NVFP4 的目标 replay 每次关联 505 个 Kernel，BF16 为 397 个，串行和并发的数量一致。两种精度均通过 B 输出与原推理工作量核验。独立 Down 实验中的 NVFP4 优势未转化为本次完整 Decode 中的更高 B 吞吐。此处的整个 Graph 包含多个算子，尚无法由阶段级轨迹定位该差异的微架构成因。

## Decode 无 Profiling 性能

| 主任务精度 | 原始推理 | 加入并发 B | 主推理变化，95% 区间 | TPOT 平均变化 | 联合完成速度，相对同工作量实测阶段串行 |
| --- | ---: | ---: | ---: | ---: | ---: |
| NVFP4 | 2149.218 ms | 2155.742 ms | +0.31%，−0.49% 至 +1.10% | +0.19% | 1.0022×，0.9975–1.0068× |
| BF16 | 4076.167 ms | 4079.035 ms | +0.07%，−0.18% 至 +0.32% | −0.01% | 0.9996×，0.9993–1.0000× |

两种主任务均能在完整请求执行中低干扰地容纳这 32 次短探针。相对于等工作量的实测串行，观察不到可复现的实质联合收益。NVFP4 空提交对照的完整请求变化为 +0.27%，与并发的 +0.31% 同量级。NVFP4 P2 记录的全部 A/B Kernel 重叠约 0.613 ms，约为 NVFP4 P0 完整请求窗口的 0.029%，量级上难以改变请求时间。固定 BF16 模型内、固定 NVFP4 模型内各条件生成 Token 的 Hash 分别一致。该探针用于验证执行共存，暂无真实推理消费者。

## Prefill 独立注入

首次试点先提交 B，再由主机准备 Prefill。探针比真实 Prefill Kernel 起点早约 752 μs 完成，实际重叠为零。调整后，先在主 Stream 记录输入依赖，再从 CPU 排入真实 Prefill 工作，随后在独立 Stream 提交 B。实测串行继续用主 Stream 等待 B 完成再开始目标 Prefill。原始失败方式有单独的 P2 档案。

| 精度 | 并发 B Kernel 时长 | 实测串行 B Kernel 时长 | Prefill 并发阶段归一化吞吐 | TTFT 平均变化，95% 区间 |
| --- | ---: | ---: | ---: | ---: |
| NVFP4 | 86.818 μs | 17.792 μs | 20.5% | +0.31%，−3.36% 至 +3.98% |
| BF16 | 154.628 μs | 17.761 μs | 11.5% | +0.39%，−0.23% 至 +1.02% |

两档并发各有一次实际 GPU 时间重叠，两个阶段串行的重叠均为零。目标阶段计算 16,384 个 Prefill Token。并发 P2 的 Prefill GPU Kernel 起止跨度为 NVFP4 302.668 ms、BF16 1187.449 ms。跨度包含阶段内 GPU 时间间隔，逐 Kernel 并集另存。P0 的完整请求变化为 NVFP4 −0.01%、BF16 +0.11%，等量阶段串行的联合速度分别为 1.0002×、0.9999×，两者描述性区间均跨 1。每种精度的 Prefill 探针时间只有一份并发和一份串行轨迹，跨精度的阶段排序仍需独立重复。 [Prefill 配对统计](analysis/gate44_20261119/prefill/statistics.csv)

## 请求生命周期联合注入

每次请求组在 Prefill 注入一次，在指定 Decode 步注入 32 次。两个模型均为 33/33 个探针与目标 GPU 活动重叠，阶段串行负对照均为 0/33。合计可见重叠约为 NVFP4 0.696 ms、BF16 0.663 ms。

| 主任务精度 | 原始推理 | 加入并发 B | 主推理变化，95% 区间 | TPOT 平均变化 | 联合完成速度，95% 区间 |
| --- | ---: | ---: | ---: | ---: | ---: |
| NVFP4 | 2151.799 ms | 2157.273 ms | +0.26%，−0.41% 至 +0.92% | +0.07% | 1.0004×，0.9992–1.0016× |
| BF16 | 4079.068 ms | 4082.381 ms | +0.08%，−0.11% 至 +0.27% | +0.04% | 0.9999×，0.9984–1.0013× |

生命周期轨迹复现了阶段间的辅助竞争排序。Decode 的条件吞吐约为 NVFP4 80.1%、BF16 89.9%，Prefill 为 NVFP4 20.7%、BF16 12.0%。相同探针的阶段排名反向，完整路径的资源共存需要按阶段讨论。阶段内的具体算子、CTA 放置与缓存竞争机制还需独立诊断。[生命周期统计](analysis/gate44_20261119/lifecycle/statistics.csv) · [已验证 P2 阶段对照](analysis/gate44_20261119/trace_summary.csv) · [结果图](figures/gate44_20261119.png)

Gate 4.4 的代表性 E2 矩阵覆盖三阶段、两种精度，每种组合完成五个配对块，共 120 次无 Profiling 推理。另保留 12 份正式 CUDA 时间线及一份早期提交的零重叠试点。固定探针在完整请求中可以实际完成，所测规模下的联合速度接近 1×。实际下游消费者和服务收益留待 Gate 4.5，需计入依赖、额外准备和真实工作量。共享卡于 12:56:58 复核无计算进程及实验许可残留。[结束检查](analysis/gate44_20261119/release_status.json)

## 执行与复核

运行入口为 `src/run_gate44.py`，通过已有 E2 supervisor 做授权范围、GPU UUID、计算进程、控制器、进程组和硬超时检查。授权按单次运行绑定精度、阶段、条件、Profiling 类型。原有 Gate 2/3 输入与基线沿用原档案。先从已授权窗口配置副本设置对应时间和实验条件，再以 `--config`、`--run-id`、`--profile`、`--phase`、`--condition`、`--window`、`--timeout` 和 `--execute` 执行。P2 的原始 NSYS 报告和 SQLite 在服务器，由保存的 SHA256 与精简活动证明关联。
