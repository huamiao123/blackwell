# RTX 5090 上 NVFP4 与 BF16 Decode 的显存读取竞争

在同一张 5090、同一 E2 工作负载上，两种精度都允许独立的流式读取与目标 Decode Graph 重叠。本次并发读取保留各自同阶段串行吞吐的 **86.3%（NVFP4）和 84.7%（BF16）**。两者相差约 1.6 个百分点。每个条件目前有一份独立 P2，不能据此判定 NVFP4 有稳定的带宽并发优势。此前的 Tensor 探针在相同 Decode 注入位置表现出另一种排序，两种探针的工作内容和持续时间不同。[时间线对照](analysis/dram_20261119/probe_competition.csv) · [此前的 Tensor 探针复验](phase_recheck_20261119.md)

## 实验条件

真实 Qwen3-8B BF16 和 NVIDIA NVFP4，Batch 8，每请求 2048 个不同的受控输入 token、257 个输出 token，256 次 Decode，CUDA Graph、FP8 E4M3 KV，关闭 Prefix Cache 和 Chunked Prefill。B 使用独立 CUDA Stream，读取与模型权重独立的确定性伪随机缓冲区。运行时读取到 L2 容量为 96 MiB，每次探针读取 384 MiB，计算 12,288 个 tile 的加权校验值，写出 48 KiB。校验按 uint32 模加，全量比对 CPU 参考。不同注入位置使用独立输出缓冲，预填为各自期望值的按位取反值。

预先选定 read/light，128 CTA，32 threads/CTA，53 registers/thread，0 B 动态共享内存，包含读取和校验计算。每个完整请求组在 Decode 第 33–64 次 replay 各注入一次，合计 **12 GiB 逻辑读取**。两种精度和两个提交条件的输入、工作量相同，核验了同精度的生成 token 哈希。并发时探针与模型共同运行，串行时主 Stream 等它完成后再执行目标 Graph。串行与并发取自独立进程。[运行索引](analysis/dram_20261119/run_inventory.csv)

## 探针独立验收

六种实际加载的 CUDA Kernel 均通过输出校验。表中独立带宽按 P0 CUDA Event 中位耗时计算，复制计入两侧字节。P1 的百分比为设备读写活动，精确物理字节数未采得。10 kHz 采样只纳入前、后相邻采样点都位于同一 GPU Kernel 内的观测。35 ms 背景对照取中段，317 个样本，平均 DRAM Read 0.006%、Write 0%。

| 探针 | 独立逻辑 GB/s | P1 设备读 / 写（%） | 合格时段内样本 | 流量方向验收 |
|---|---:|---:|---:|---|
| Read Light | 557 | 32.7 / 1.0 | 47 | 通过 |
| Read Heavy | 1,035 | 61.9 / 1.0 | 16 | 通过 |
| Write Light | 1,656 | 0.0 / 96.0 | 3 | 样本不足 |
| Write Heavy | 1,638 | 0.2 / 96.0 | 5 | 通过 |
| Copy Light | 97 | 2.9 / 2.9 | 726 | 通过 |
| Copy Heavy | 1,349 | 39.2 / 39.2 | 36 | 通过 |

方向验收要求至少 5 个内点样本，且相应读或写活动高于背景至少 1 个百分点。Write Light 的三个样本均显示强写入，保留待补采状态。Copy Light 的低带宽在 P0 和 P1 中均出现，本轮没有对其微架构原因做归因。[独立计时与资源属性](analysis/dram_20261119/standalone.csv) · [硬件采样](analysis/dram_20261119/acceptance.json)

## 完整推理中的实际竞争

| 主任务 | B 串行中位时长 | B 并发中位时长 | B 并发逻辑读取 | 吞吐保持率 | B 执行时间与主 Kernel 并集相交 |
|---|---:|---:|---:|---:|---:|
| NVFP4 | 696.0 µs | 805.5 µs | 500.4 GB/s | 86.3% | 98.7% |
| BF16 | 689.6 µs | 813.8 µs | 494.6 GB/s | 84.7% | 99.3% |

保持率为固定工作量下 32 次 B 的串行 GPU 时长之和除以并发 GPU 时长之和。独立运行带宽、推理中的条件串行带宽分别记录。两个模型均验证同一 CUDA Context、独立 Stream、32/32 次 GPU 重叠，串行均为 0/32。核对目标 Graph 的 Kernel 个数，按主 Kernel 区间并集去重。并发探针中位起点分别比第一个目标主 Kernel 早 0.544 µs 和 1.216 µs。

主 Graph 的平均首末 Kernel 跨度，在 NVFP4 上从串行对照的 6.433 ms 增到并发的 6.647 ms，在 BF16 上从 10.496 ms 增到 10.826 ms。此计时排除了串行方案中提前完成的 B，描述 P2 下的目标 Graph 区间。完整请求的无 Profiling 延迟损失与联合收益仍待 P0 配对测量。GPU 时间重叠也不能定位 CTA 具体驻留在哪个 SM。[逐次 GPU 起止与原始日志](raw/dram_20261119/)

## 阶段平均带宽与这个探针的关系

用此前冻结的无探针 P1 做 CPU 复算，分别取本次涉及的 32 个 Decode replay 的前 500 µs。每种精度各有 96 个内点样本，设备平均 DRAM Read 为 NVFP4 **45.5%**、BF16 **82.5%**。这个更靠近探针入场位置的无探针对照仍保留约 37 个百分点的差异，而并发时辅助读取吞吐只相差约 1.6 个百分点。由主任务平均带宽直接推算“可分配带宽”没有得到本配置的支持。探针自身的 Grid、访存并行度、校验计算以及两个任务的调度都可能影响结果。两轮 P1/P2 来自独立进程，未跨采集对齐绝对时间戳。带探针时的实际设备级带宽与争用原因仍待同条件 P1。[首 500 µs 对照](analysis/dram_20261119/baseline/)

## 共享卡与未完成项

首次启动缺少远端 CPU 参考模块，第二次在取得当前 CUDA Context 前查询设备属性。补齐依赖并在 Driver API 调用前显式建立当前设备上下文后，通过独立验收。四份模型 P2 都正常结束。末份 BF16 串行采集监督结束于北京时间 14:33:14.622；14:33:18.328 下一次预检发现其他计算进程，监督器在创建 GPU 工作负载前退出。记录仅限定观测时刻。之后的分析全部使用已有文件。[失败及预检记录](analysis/dram_20261119/failed_runs.csv)

待继续的项目为增加 Write Light 内点样本、两种精度相同注入位置的 P0 五个配对块、并发和串行的 E2 P1 带宽采样，以及关键差值的独立进程复测。当前不报告端到端加速或直接同 SM 共驻。

## 复核

每次运行使用 `src/run_dram_supervised.py`，继承原 E2 的限时窗口、进程监督、UUID 核验与清理。独立验收用 `--phase dram_standalone --condition acceptance --profile P0|P1`，配置文件仅用于监督和许可，未加载模型。完整 E2 时间线用 `--phase dram_decode --condition parallel|serial --profile P2`。完整命令和环境在相应监督日志。部署时需保留 `gate4_spatial/src/dram_reference.py`、独立编译的 cubin 与编译清单，GPU 上的加载结果按哈希核对。推理试点还核对本次 `acceptance.json` 的设备、二进制和读方向验收状态。

`analyze_dram_acceptance.py` 读 P1 SQLite，`analyze_gate44_trace.py` 关联 P2 区间，`summarize_dram_study.py` 汇总同工作量对照。后续 P1 设备窗口和 P0 输出间隔的分析代码已准备，本次无对应实测文件。
