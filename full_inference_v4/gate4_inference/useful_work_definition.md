# 什么才算有用的额外计算

FP32 FMA和BF16 MMA Probe用于测竞争，结果无真实消费者时不能成为推理优化。候选必须原本就需要、输入已可用、不依赖未来Token或下一层尚未产生的激活、不改变数值语义，并由真实后续计算消费。

`useful_work.py`记录输入/输出契约Hash、真实consumer IDs、原始必要性、生产依赖、要求单位、实际完成与输出Hash。禁止重复准备、未就绪生产、重复/未知消费者及读取旧结果。结束时要求所有声明消费者实际消费正确输出。

尚未选择候选。数据layout、量化准备、KV维护、独立请求准备只是待查类型；每项先审查源码中的原始执行位置、生产者和消费者，不能把新增加的可并发计算当成省下必要工作。

未来验收表至少应包括：原始调用位置、输入产生事件、允许提前的最早时刻、真实消费者调用位置、输出一致性、是否替代原操作、是否重复、截止时间、总有效工作量及P0收益。仅Hash一致不足以证明已经接入消费者，须通过真实运行关联与结果检验。

`UsefulWork`是代码级契约，不是当前已经发生的实际消费证据。
