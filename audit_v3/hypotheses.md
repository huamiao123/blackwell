# hypotheses.md — 可证伪的机制假设

每条假设都写明：**主张 / 支持证据 / 反对证据 / 如何证伪**。
当前状态：Gate 1 只做了 tensor 探针 + 3 个 M，因此没有一条能被"证实"，最多是"未被否证"。

---

## H1｜BF16 在大 M 时受非 tensor 资源限制，因此 tensor pipe 真的有余量

**主张**：M=1024、BF16 的 GEMM 达到 212 TF（不到理论 419 的一半），瓶颈不在 tensor 指令吞吐，
而在 epilogue/写回/issue 等其它环节。因此额外 tensor 工作可以几乎免费地插入。

**支持**：
- S_A = 1.048（塞入同规模 tensor 探针，主任务只慢 4.8%）——`raw/gate1_v2.json`
- S_B = 1.895（探针自己被拖慢 89.5%）：说明资源是被主任务占着的，但主任务不受影响，
  即"探针抢的东西主任务不缺"。

**反对**：
- 物理 kernel 重叠只有 **28.5%**（`raw/timeline_overlap.json`）。如果真是"资源有余、可随时插入"，
  重叠应该更高。当前更像是两者在 kernel 粒度上轮流占用，主任务只是"不怎么受影响"。
- 212 TF 与理论 419 TF 的差额**不能**直接解释成空闲 tensor core（纪律第 9 条）。

**证伪实验**：把探针的 grid 限制到 k 个 CTA（k = 1, 4, 16, 64, 170），观察
`kernel_overlap` 与 `S_A` 如何随 k 变化。
- 若小 grid 下重叠接近 100% 且 S_A≈1 → H1 成立（可共驻、有余量）。
- 若任何 k 下都无法提高重叠 → 说明是调度/驻留限制，H1 不成立。

## H2｜FP4 在大 M 时把 tensor pipe 吃满，因此 tensor 竞争真实存在

**主张**：FP4 达到 1156 TF（理论 1676 的 69%），tensor 指令发射接近饱和，
任何额外 tensor 工作都会直接抢同一个流水线。

**支持**：
- S_A = 1.570 且 S_B = 1.486（M=1024）：**双方都变慢**，这是真竞争的特征
  （H1 那种"一方不变、一方被拖"不是）。
- 物理 kernel 重叠 61.2%，高于 BF16 同条件下的 28.5%。

**反对**：
- 69% 仍然是"距离理论峰值还有 31%"，也可能只是数据供给不足，而不是发射饱和。

**证伪实验**：
- 用 **FP4 tensor 探针**（而非 BF16）复用主任务的同一 kernel 家族；
  若 S_A 进一步上升 → tensor 流水线是真瓶颈。
- 反过来用 **纯 FP32 FMA 探针**（重写后的）做对照：
  若 FP32 探针对 FP4 主任务几乎无影响，则排除"通用 issue 饱和"，H2 成立。

## H3｜当前的"并发"主要是 kernel 粒度时间片交替，不是同 SM 共驻

**主张**：两个满网格的 GEMM（主任务 192–1536 CTA，探针 256 CTA）都无法同时驻留在
170 个 SM 上，GPU 只能在 kernel 边界切换。所谓"并发"是交替执行 + 边界交叠。

**支持**：
- 重叠率与减速比不单调：M=1024/BF16 重叠仅 28.5%，S_A 却是最低的 1.048；
  M=16/BF16 重叠 87.1%，S_A 反而 1.755。若重叠=竞争，这条关系应该是单调的。
- 主任务 kernel 时长（M=16: ~30 µs）与探针 kernel 时长（~96 µs）都远大于切换成本，
  时间片交替在时间线上就会表现为"部分重叠 + 长尾"。

**反对**：
- 我们没有任何 SM 级证据（无 NCU、无 nsys 时间线核验）。重叠 ≠ 共驻，但没有反证。

**证伪实验**：
- **限制 CTA 数**：把探针 grid 设为 1/4/16 个 CTA，主任务保持满网格。
  若能观察到 `kernel_overlap` 上升且 `S_A` 下降，说明共驻是可能的，只是需要留出 SM。
- 反之若限制 CTA 后重叠仍不上升，则是调度器或资源粒度限制（例如每 CTA 86 KB SMEM
  导致一个 SM 只能放一个 CTA）。

## H4｜"空闲算力"不可回收为端到端收益

**主张**：即使存在 tensor 余量，实际可用的场景也不存在：
要么主任务已经很快（省 4.8% 没有意义），要么插入的辅助工作本身有依赖/带宽代价。

**支持**：
- 全部 6 个 Gate 1 条件的 G 只有 1.09–1.25，且 BF16 M=1024 那格 S_A=1.048 的同时
  S_B=1.895——辅助任务被拖慢近一倍，**它的绝对完成量并没有变多**。

**反对**：
- Gate 1 只用了合成探针，没有用"真实有用任务"（投机解码验证、KV 量化等）。

**证伪实验**：Gate 4 用真实依赖合法的辅助任务（如 gate/up 双分支）测 makespan，
必须打赢**同精度下的最佳串行/融合基线**，而不是打赢人为拆分的弱基线。

## H5｜S_A 的绝对值对提交协议高度敏感，但"哪种精度更抗干扰"的排序相对稳健

**主张**：修协议后数值变了（最多 −0.63 / +0.62），但 BF16 在大 M 更抗 tensor 干扰这一
定性排序不变。

**支持**：
- 修正前后 M=1024：BF16 1.048/0.415，FP4 1.570/1.296——两种协议下 FP4 都更敏感。
- M=128 的 FP4 从 1.345 变到 1.646，**排序在这一点上翻转风险存在**（旧数据说 FP4 更抗，
  新数据说更敏感），因此该点必须重测。

**反对**：样本只有 3 个 M、3 个会话。

**证伪实验**：Gate 3 全 M × 3 会话 × 两种提交顺序，检查排序是否稳定；
若 M=128 的排序在多次重复中不稳定，则所有"M 方向的交叉"结论都必须撤回。
